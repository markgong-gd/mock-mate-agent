# 01 · 产品需求

> 来源：Deep Research 研究报告 `note_20261022_162541_3`（2026-10-22）。本文是 MockMate 的**需求基准**，回答“做什么、为谁做、做到什么程度、不做什么”。
> 技术实现见 [02 · 技术选型与技术架构](02-architecture.md)，落地排期见 [03 · 落地计划](03-delivery-plan.md)。

## 1. 产品目标

MockMate 是一个**求职者侧**智能面试 Agent，围绕 **职业档案 → 简历定制 → 模拟面试 → 能力诊断 → 定向复训** 形成闭环。

| 编号 | 能力 | 描述 |
|---|---|---|
| C1 | 简历定制 | 结合求职者的工作经验、经历以及目标岗位要求（JD），生成对应的定制简历。也可以不针对 JD，按档案和简历标准生成主简历 |
| C2 | 面试训练 | 根据目标岗位要求，与求职者完成多轮、可追问的模拟面试（先文字，后语音） |
| C3 | 诊断与复训 | 根据面试表现，自动总结求职者相对目标岗位欠缺的能力，并针对性生成训练 |

## 2. 目标市场与定位

### 2.1 目标市场

| 项 | 结论 |
|---|---|
| 项目性质 | **个人项目**（1 人开发，带学习性质）。当前以个人使用为主，对外开放为后续可选；需求按“个人使用阶段”和“对外开放前”两档执行 |
| 地域 | **中国大陆** |
| 语言 | 中文为主（简历、JD、面试对话、诊断报告均以中文为默认） |
| 用户 | 求职者（C 端），首批聚焦互联网技术岗位（前端岗位优先，与初版题库一致） |
| 合规依据 | 《个人信息保护法》（PIPL）、《生成式人工智能服务管理暂行办法》、《人工智能生成合成内容标识办法》；就业公平参照《就业促进法》 |
| 模型约束 | 模型 provider 可替换。个人使用阶段可接入个人付费模型；对外开放前只使用已完成备案的国内大模型服务 |
| 数据约束 | 用户数据境内存储与处理。个人使用阶段若选用境外模型，发送给模型的内容会出境，由本人知情决定；对外开放前不出境 |
| 部署约束 | 优先本地可运行；其次可部署到免费平台个人使用，国内平台优先 |

> 原调研中的量化证据与监管案例主要来自美国（见 §7、§6 R2），只作参考，国内数据待补充。

### 2.2 定位

- **核心差异化**：不做“实时喂答案”，做的是 **“档案 → 简历 → 训练 → 诊断 → 定向复训”的闭环**。
- **产品边界**：只做事前训练和事后诊断，不提供真实面试中的实时代答（见 R-B-1）。

## 3. 功能需求

### 3.1 业务闭环

```text
          +------------------------------------+
          |  统一职业档案                        |<---- 上传简历 / 表单采集 / 用户确认
          |  经历 / 事实 / 技能 / 短板 / 得分历史 |
          +----+--------------+-------------+--+
               |              |             ^
      档案 + JD |  档案+JD+短板  |             | 短板写回、得分更新 (R-P3)
               v              v             |
         +-----------+  +-----------+  +-----------+
         | C1 简历定制 |  | C2 模拟面试 |->| C3 诊断   |
         +-----+-----+  +-----+-----+  +-----+-----+
               |              ^              |
               v              +--------------+
           导出 PDF            复训计划 / 专项训练
```

### 3.2 账户与职业档案（三大能力共享的数据底座）

| ID | 需求 | 说明 |
|---|---|---|
| R-A-1 | 用户账户：注册 / 登录 / 退出 | **优先级低，列为待补项，对外开放前必须完成**。个人使用阶段为单用户模式，但所有数据从第一天起归属到 `userId`；部署到公网时必须有访问口令保护 |
| R-P1 | 上传 PDF 简历，自动抽取为结构化档案 | 包括经历、可溯源的事实条目、技能 |
| R-P2 | 抽取结果经用户确认 / 编辑后才入库 | 保证数据质量（对应风险 R6） |
| R-P3 | 档案跨会话持续累积 | 诊断出的短板、技能得分写回档案，写回时合并、去重并更新得分（档案复利） |
| R-P4 | 可从表单采集技术栈和能力，不必先有简历 PDF | 技能含熟练度：用过 / 熟练 / 深入。标为深入必须关联至少一条本档案中的事实。经历仍至少一条可核对事实。确认后才入库，与上传解析走同一个保存接口。教育经历与作品链接不在本阶段 |

### 3.3 C1 简历定制

| ID | 需求 | 说明 |
|---|---|---|
| R-C1-1 | 粘贴 JD，抽取结构化技能要求 | — |
| R-C1-2 | 展示档案与 JD 的匹配度和技能缺口 | 技能缺口同时用于优化简历和安排面试训练 |
| R-C1-3 | 基于档案 + JD 生成定制简历，边生成边预览 | — |
| R-C1-4 | **每条简历描述必须关联档案中的事实，禁止编造** | 无法溯源的内容要标记出来，且不能导出（对应风险 R1） |
| R-C1-5 | 简历可编辑，同一 JD 或同一份主简历可保存多个版本 | — |
| R-C1-6 | 导出 PDF（至少 1 套模板） | — |
| R-C1-7 | 没有 JD 时，按档案生成主简历，边生成边预览 | 与岗位定制共用同一张简历图、同一套正文结构。主简历不针对具体岗位 |
| R-C1-8 | 简历质量标准版本化，生成和编辑后展示检查结果 | 标准是纯函数，当前版本 `resume-standard@1`。标准只约束写法和结构，不能用来编造经历。检查结果分 error / warning，都只展示；导出仍只拒绝未溯源条目（R-C1-4） |

**简历标准 `resume-standard@1`**（只检查能从档案和正文判定的项）：

| 级别 | 代码 | 规则 |
|---|---|---|
| error | `skill_not_in_profile` | 「技能」栏目里出现档案没有的技能标签 |
| warning | `proficiency_upgrade` | 「技能」栏目写了「精通」，但档案里该标签的熟练度不是深入 |
| warning | `dropped_number` | 被引用事实中的数字没有出现在对应描述里 |
| warning | `empty_phrase` | 描述以「负责 / 参与 / 熟悉 / 了解 / 学习能力强 / 吃苦耐劳」开头，且没有数字 |
| warning | `too_many_bullets` | 同一栏目超过 5 条 |
| warning | `section_order` | 同时有「技能」和经历栏目时，技能在经历之前；有「教育」时教育在最后 |

深入（`expert`）没有证据事实时，在保存档案时拒绝，不放到简历标准里再判一次。

### 3.4 C2 模拟面试

| ID | 需求 | 说明 |
|---|---|---|
| R-C2-1 | 面试设置：选择目标岗位、题数、难度、面试风格 | — |
| R-C2-2 | 基于 JD 技能点 + 档案 + 题库出题 | 题目要和 JD 相关 |
| R-C2-3 | 回答浅或含糊时自动追问，单题追问次数有上限 | 多轮自适应追问是一流产品和普通产品的分水岭 |
| R-C2-4 | 优先针对历史短板出题 | 闭环的关键 |
| R-C2-5 | 专项训练：只针对单个短板练习 | 可从诊断报告一键进入 |
| R-C2-6 | 中断（刷新 / 断网 / 语音断线）后可以继续，回答不丢失 | 文字和语音都适用 |
| R-C2-7 | 语音面试：实时语音一问一答 | 阶段 4；延迟目标在语音方案调研时确定 |
| R-C2-8 | 语音面试支持打断 | 用户插话时面试官停止播报，回应插话内容 |
| R-C2-9 | 语音面试提供实时字幕和计时 | — |
| R-C2-10 | 语音和文字面试共用题目、追问逻辑和诊断 | 语音面试同样生成诊断报告 |

面试流程（产品视角）：

```text
  +------+    +---------+    +-------------+
  | 出题  |--->| 等待回答 |--->| 是否需要追问? |
  +------+    +---------+    +------+------+
     ^             ^          是 |      | 否
     |             |             v      v
     |             |      +--------+  +-----------+  是  +-------------+
     |             +------| 生成追问 |  | 题目用尽?  |---->| 结束 -> 诊断  |
     |                    +--------+  +-----+-----+     +-------------+
     |                                      | 否
     +--------------------------------------+
```

### 3.5 C3 诊断与复训

| ID | 需求 | 说明 |
|---|---|---|
| R-C3-1 | 按多维 Rubric 逐题打分，并给出整体评分 | 维度见下表 |
| R-C3-2 | 提取短板：关联 JD 技能点，附回答原话作为证据 | 每个短板都要有证据；写回档案的规则见 R-P3 |
| R-C3-3 | 诊断报告：雷达图 + 逐题点评 + 改进建议 | — |
| R-C3-4 | 根据短板生成复训计划 | — |
| R-C3-5 | 成长曲线：同一技能多次诊断的得分趋势 | — |
| R-C3-6 | Rubric 透明、版本化 | 维度和评分标准对用户可见；每份报告记录所用 Rubric 版本；Rubric 修改后要先通过一致性评测才能上线（对应风险 R2） |

**Rubric 初版维度**：

| 维度 | 说明 |
|---|---|
| 技术深度 | 回答对 JD 技能点的掌握程度 |
| 结构化表达 | 是否符合 STAR 等结构 |
| 岗位匹配度 | 经历与 JD 要求的契合程度 |
| 沟通流畅度 | 表达是否清晰、简洁（语音阶段加入语速、停顿、口头禅） |

### 3.6 产品边界

| ID | 需求 | 说明 |
|---|---|---|
| R-B-1 | 不提供真实面试中的实时代答 / 作弊辅助 | 不做以下功能：监听真实面试并实时提示答案、屏幕识题、隐藏式提词等（对应风险 R4） |

## 4. 非功能需求

| ID | 类别 | 需求 |
|---|---|---|
| N-1 | 隐私 | PII 最小化存储：只保存用户确认后的结构化档案，不保存非必要字段 |
| N-2 | 隐私 | 默认不保存简历原文件，解析完成后即丢弃 |
| N-3 | 隐私 | 发送给模型、写入日志或 Trace 之前，脱敏手机号、邮箱、证件号 |
| N-4 | 隐私 | 上传前告知用途，并单独征得用户同意；不同意不能上传 |
| N-5 | 隐私 | 支持一键删除档案和全部会话数据，数据库、Trace、日志中都不能留存；备份中的数据在保留期到期后清除 |
| N-6 | 安全 | 用户只能访问自己的数据（含越权防护） |
| N-7 | 安全 | 模型密钥等长期凭证不暴露给客户端；客户端只拿短期 token |
| N-8 | 公平 | Rubric 与 Prompt 不使用受保护特征（性别、年龄、民族、婚育等），并有回归检查 |
| N-9 | 可靠 | 模型调用失败时给出提示并降级处理，面试进度和已有简历版本不丢失 |
| N-10 | 质量 | 简历生成、出题、诊断都有评测集和回归机制，防止幻觉与评分漂移 |
| N-11 | 体验 | 简历生成和面试对话流式输出；诊断异步进行，不阻塞页面 |
| N-12 | 成本 | 可统计单次面试的 Token 用量和成本；高成本接口要限流 |
| N-13 | 合规 | 用户数据境内存储和处理。个人使用阶段选用境外模型时，在隐私说明中写明模型内容出境；对外开放前不出境 |
| N-14 | 合规 | 对外开放前只使用已备案的大模型服务（通过 provider 白名单开关控制）；按标识办法对 AI 生成内容做标识（适用范围上线前请合规确认） |
| N-15 | 可移植 | 本地一条命令启动数据库、一条命令启动应用；可打包为单镜像部署到免费容器平台 |
| N-16 | 可替换 | 模型 provider 可替换：业务只依赖模型别名，切换 provider 或模型只改配置，不改代码 |

## 5. 核心洞见

1. **统一职业档案是数据底座**：三大能力共享这份档案，支持跨会话记忆，也能针对不同岗位分别使用；档案越完善，简历和面试越精准。
2. **简历 + JD 双上下文驱动**：岗位定制贯穿后续面试；没有 JD 时仍可按档案生成主简历。技能缺口同时用于优化简历和安排面试训练。
3. **实时双向、多轮自适应对话是一流产品的分水岭**；**能力诊断闭环**是竞品（如 Final Round AI 侧重实时喂答案）没做的差异化空档。
4. **C3 的落地链路**：多维 Rubric + 短板诊断 + 自适应训练。
5. **推荐架构方向**：循环编排 + 三专职 Agent（简历 / 面试官 / 诊断）+ 知识层（MCP / RAG）+ 分层记忆 + 可观测兜底。

## 6. 风险与应对

| # | 风险 | 应对方向 | 对应需求 |
|---|---|---|---|
| R1 | 幻觉编造（简历虚构经历） | 职业事实库 + 事实溯源 | R-C1-4、N-10 |
| R2 | 算法偏见与监管风险（国内：PIPL、生成式 AI 管理办法、就业歧视；原调研中的海外参照：FTC / EEOC / GDPR / Illinois AI Video Interview Act） | Rubric 透明化并版本化、评分一致性评测、不使用受保护特征 | R-C3-1、R-C3-6、N-8 |
| R3 | 数据隐私（简历含大量 PII，证件号等属于敏感个人信息） | 最小化存储、单独同意、可删除、脱敏、境内存储 | N-1 ~ N-5、N-13 |
| R4 | 实时辅助的作弊伦理灰色地带 | 只做事前训练和事后诊断，不做实时代答 | R-B-1 |
| R5 | 协调架构失败（>60% 的企业 AI 项目因此失败） | 重试 / 回退 / 全链路可观测 | N-9 |
| R6 | 数据质量依赖（JD、题库、档案） | 结构化抽取 + 校验 + 用户确认 | R-P2 |
| R7 | 赛道拥挤、产品同质化 | 护城河 = 诊断训练闭环 + 隐私合规 | §3.1、§4 |
| R8 | 模型与内容合规（模型未备案、AI 内容未标识） | 个人使用阶段由本人选择模型；对外开放前收紧为已备案模型，按规定标识并做合规评估 | N-13、N-14、N-16 |
| R9 | 免费平台政策变化或能力受限（休眠、时长、存储） | 本地优先；平台相关代码收口；定期备份；保留自有机器与轻量服务器兜底 | N-15 |

### 本次修订收紧的约束

| 约束 | 原表述 | 现表述 | 原因 |
|---|---|---|---|
| 账户前置 | 用户认证放在 P5（上线前）实现 | 未登录不能使用任何功能（R-A-1） | 数据要从第一天起就归属到账户，避免后续迁移和越权隐患 |
| 授权方式 | 上传前明确告知用途并取得授权 | **单独同意**，不同意不能上传（N-4） | 简历可能含证件号，属于 PIPL 规定的敏感个人信息 |
| 删除范围 | 删除后数据库中无残留 | 数据库、Trace、日志都不能留存；备份在保留期到期后清除（N-5） | 原表述没有覆盖观测数据和备份 |
| 脱敏范围 | 发送给模型、写入 Trace 前脱敏 | 增加**日志**（N-3） | 日志同样可能泄露 PII |
| 简历原文件 | 最小化上传 | 默认不保存原文件，解析完即丢弃（N-2） | 明确最小化存储的边界 |
| 数据地域 | 无 | 境内存储和处理，不出境（N-13） | 目标市场为中国大陆 |
| 模型选择 | 通过 Provider 切换，不绑定厂商 | 只能在**已备案模型**范围内切换（N-14） | 生成式 AI 管理办法 |
| AI 内容标识 | 无 | 按标识办法标识 AI 生成内容（N-14） | 生成合成内容标识办法 |
