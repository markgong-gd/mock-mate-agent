# 01 · 产品调研：求职者侧智能面试 Agent

> 来源：Deep Research 研究报告 `note_20261022_162541_3`（2026-10-22），本文为其要点整理，作为产品需求基准。

## 1. 产品目标

MockMate 是一个**求职者侧**智能面试 Agent，需具备三大核心能力：

| 编号 | 能力 | 描述 |
|---|---|---|
| C1 | 简历定制 | 结合求职者的工作经验、经历以及目标公司岗位要求（JD），帮助求职者制作对应简历 |
| C2 | 面试训练 | 根据目标公司岗位要求，与求职者完成模拟面试训练 |
| C3 | 诊断与复训 | 根据本次面试练习，自动总结求职者相对目标岗位欠缺的能力，并针对性生成面试训练 |

研究主题概括：**简历制作 → 面试训练 → 能力诊断与定向复训**。

## 2. 五大核心洞见

1. **统一职业档案是数据底座**
   以"统一职业档案"作为三大能力共享的数据底座，支持跨会话记忆与多岗位投影（档案复利：档案越完善，后续每次简历与面试越精准）。
2. **简历 + JD 双上下文驱动**
   "简历 + JD"双上下文贯穿全流程，技能缺口数据同时驱动简历优化与面试训练。
3. **实时双向多轮自适应对话是分水岭**
   实时双向、多轮、自适应追问是一流产品的分水岭；**能力诊断闭环**是竞品（如 Final Round AI 侧重实时喂答案）留下的差异化空档。
4. **能力 3 的落地链路**
   "多维 Rubric + NLP 短板诊断 + 自适应训练"构成能力 3 的落地链路。
5. **推荐架构**
   循环编排（LangGraph 类）+ 三专职 Agent（简历 / 面试官 / 诊断）+ MCP/RAG 知识层 + 分层记忆（情景 + 持久）+ 可观测兜底（LangSmith 类）。

## 3. 七项主要风险与应对

| # | 风险 | 应对方向 |
|---|---|---|
| R1 | 幻觉编造（简历虚构经历） | 职业事实库 + 事实溯源（每条简历描述须关联档案事实） |
| R2 | 算法偏见与监管执法（FTC / EEOC / GDPR / Illinois AI Video Interview Act） | Rubric 透明化、评分一致性评测、避免使用受保护特征 |
| R3 | 数据隐私（简历含大量 PII） | 最小化上传、可删除、明确授权、PII 脱敏 |
| R4 | 实时辅助的作弊伦理灰色地带 | **产品定位聚焦事前训练 + 事后诊断，不做真实面试实时代答** |
| R5 | 协调架构失败（>60% 企业 AI 项目因此失败） | 重试 / 回退 / 全链路可观测 |
| R6 | 数据质量依赖（JD、题库、档案质量） | 结构化抽取 + 校验 + 用户确认环节 |
| R7 | 赛道拥挤同质化 | 护城河 = 诊断训练闭环 + 隐私合规 |

## 4. 关键量化证据

| 指标 | 数据 |
|---|---|
| 单岗位平均申请数 | 242 份 |
| ATS 拒绝率 | 90%+ 简历被 ATS 筛掉 |
| 求职周期 | 55–71 天 |
| 雇主重视沟通能力比例（NACE） | 73.1% |
| 简历定制对面试概率的提升 | 最高 +50% |
| 即时反馈对口语流畅度的提升 | 约 +20% |

## 5. 产品定位结论

- **用户**：求职者（C 端）。
- **核心差异化**：不是"实时喂答案"，而是 **"档案 → 简历 → 训练 → 诊断 → 定向复训"的闭环**。
- **边界**：不提供真实面试场景下的实时作弊辅助。
